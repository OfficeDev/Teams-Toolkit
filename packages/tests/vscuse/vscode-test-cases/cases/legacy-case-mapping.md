# Generated-to-Legacy Case Mapping

This mapping relates each YAML-authored case to its generated plan and the legacy VScUse plan it
replaced. It is the migration record for plans that are gone: the legacy plan column names a file
that no longer exists wherever the status is **Full**.

## Status

- **Full**: the generated case covers the legacy scenario intent with semantic steps and file
  checks, and the legacy plan has been removed.
- **Partial**: the generated case covers the legacy scaffold and lifecycle but stops short of part of
  the legacy flow, such as its chat validation or its negative input path, so the legacy plan is kept
  until that gap closes.
- **Not Mapped**: no generated case safely replaces the named legacy-specific behavior; the precise
  blocker is recorded below and the legacy plan is kept.
- **Retired**: the legacy-specific behavior is intentionally no longer tested because it is not a
  required product contract or duplicates coverage elsewhere; the legacy plan is removed without a
  generated replacement.

A generated case is still **Full** when it sends the legacy prompt and asserts an error-free reply
where the legacy plan asserted reply wording. The wording is the model's, so asserting it would tie
the case to a service this repository does not control; the legacy grounding keywords such as
`Contoso Electronics`, `Northwind Health`, and `Oil change` are that wording. The rest of the legacy
chat assertion, that no `error` appears in the reply, is asserted verbatim.

Generated OpenAI cases use `${{secret:AZURE_OPENAI_API_KEY}}` and redirect to
`${{env:AZURE_OPENAI_ENDPOINT}}/openai/v1`. Local and Playground cases set the endpoint through
`localEnvironment`; remote cases set it through `remoteEnvironment` before provision. Unsupported
hardcoded models are changed to `gpt-4o-mini`. Chat assertions expect successful replies and assert
they are error-free where the case has that check, without depending on service-owned response
wording. VCB-140 and VCB-142 define the dev behavior; the retained migrations align through VCB-145
and VCB-156.

## Backlog

- Extend `da-typespec-oauth-with-reference-id` through provision and remote Copilot chat after the
  test tenant owns a stable OAuth configuration and the runner can receive its configuration ID.
  Until then, the generated case intentionally stops after validating and packaging the TypeSpec
  source. Its all-zero UUID only satisfies package-time manifest substitution and must never be
  treated as a runtime OAuth configuration ID.
